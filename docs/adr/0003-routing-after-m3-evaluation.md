# ADR-0003：M3 评测之后，每一类判断走哪条路

**Status:** Accepted（Claude 一侧的对照列补跑后复核）；J5 一项的依据在 2026-11-17 重测后不再成立，`check` 的路由待重新决定（见文末「2026-11-17 补记」）
**Date:** 2026-11-16
**Deciders:** 项目所有者；依据方案 7.12 的评测闸与 `evals/report.md` 的实测

## Context

方案把判断交给两套模型：快系统 Jev 只做选择题，慢系统 Claude 负责写字与深思（方案 1.2）。方案同时承认 Jev 的中文能力和扮演具体人物时的准确率没有公开数据，所以规定 M3 必须先评测再定路由（7.12），并给了每类判断留在 Jev 的硬门槛。

评测在本环境里实跑了 Jev 一侧（`jev-1.14.0`，真实请求）。这里没有 Claude 的密钥，所以 C1、Haiku、Sonnet 的对照列都没有跑。约束还有两条：首字时延中位数不超过 3 秒；每回合成本不超过 2 美分（方案 11.7）。

实测结果（数据集见 `evals/data/`，报告见 `evals/report.md`）：

| 判断 | 方案的闸 | 实测 | 结论 |
| --- | --- | --- | --- |
| J1 输入归类（300 条） | 过门槛样本上一致不低于 95%，且过门槛的不少于七成 | 修补解析器前：覆盖 72.0%，六项全对 56.0%。修补后：覆盖 87.0%，六项全对 80.5% | 没过 |
| J2 角色抉择（80 个抉择点） | 过门槛样本与原著做法一致不低于 70%，且过门槛的不少于一半 | 覆盖 52.5%，一致 85.7%（三次跑的覆盖：52.5%、52.5%、55.0%） | 过，覆盖贴着线 |
| J5 叙述核对（100 句） | 检出不低于 80%，误杀不高于 10% | 评测旧排法（玩家原话接在【你做的事】后面）：门槛 0.70 检出 100%，误杀 18% 到 22%；门槛 0.80 检出 96% 到 98%，误杀 6% 到 10%。游戏里的排法（D-356，原话在最后的【玩家的话】一节；2026-11-17 四次）：门槛 0.70 检出 80% 到 82%，误杀 18% 到 20%；门槛 0.80 检出 70% 到 74%，误杀 4% 到 8% | 旧排法 0.80 时过；游戏里的排法没有一个门槛过 |
| 中英问法（240 题） | 取一致率高的 | 中文 83.3%，英文 80.0%（英文模板有几处没跟上改动） | 维持中文 |
| Jev 时延与成本（30 回合） | 中位数 3 秒；每回合 2 美分 | 首字中位数 390 毫秒，P90 708 毫秒；每回合 0.06 美分 | Jev 一侧过 |

J1 的 56% 里，一大半不是 Jev 答错，是解析器把答案落成动作的几步有缺陷（对象题不分人与物、`has_speech` 压过高置信的 `kind` 等）。修补后升到 80.5%，剩下的 67 条错多数是 Jev 自己的准确率：言语行为相近的分不清（示警与告知、求饶与请求）、动词或对象、所求之事。

## Decision

路由写进 `config.toml`，代码不变：

```toml
[route]
classify = 'claude_first'   # J1 没过闸：C1 先行，C1 不可用时退到 J1
decide_soul = 'jev_first'   # J2 过闸
decide_named = 'jev_first'
check = 'jev_first'         # J5 过闸，门槛调高
[jev.thresholds]
narration_flag = 0.80       # 原 0.70
choice_confidence = 0.55    # 不动
[jev]
lang = 'zh'
```

- **J1 归类改为 C1 先行。** 这是方案 7.12 写明的退让：「达不到时，该项默认走 C1」。没有 Claude 密钥时，C1 报不可用，解析器退到 J1；修补后 J1 比纯规则准（77.7% 对 60.3%），所以退路取 J1，不取规则。
- **J2 抉择留在 Jev。** 置信度过门槛的一半样本上，Jev 与原著做法一致 85.7%；另一半本来就会升级给 C2。
- **J5 核对留在 Jev，门槛由 0.70 调到 0.80。** 叙述被误杀的代价是丢一句话再用模板补，检出掉 4 个点换误杀降到一成以内。
- **J3、J4、J6 不设硬门槛**（方案 7.12），维持 `jev_first`，试玩时看日志。

## Options Considered

### Option A：按闸逐类定路由（采用）

| 维度 | 评估 |
| --- | --- |
| 复杂度 | 低：只改配置 |
| 成本 | 每次自由输入多一次 Haiku 调用，约 0.05 美分；其余不变 |
| 时延 | 自由输入的归类从约 0.1 秒变成一次 Haiku 的时延；选项输入不受影响 |
| 风险 | C1 的准确率在这里没有实测，是按方案的默认退让走的 |

**Pros：** 每一类都有数据支撑；过了闸的继续享受 Jev 的快与便宜；没过的按方案退让。
**Cons：** 归类这条路的最终质量要等有密钥时补跑 C1 一列才知道。

### Option B：全部改走 Claude（`claude_only`）

| 维度 | 评估 |
| --- | --- |
| 复杂度 | 低 |
| 成本 | 高：每回合十几次判断都走 Claude，估计是现在的十倍以上 |
| 时延 | 在场每人一次 C2，首字时延难以守住 3 秒 |
| 风险 | 低 |

**Pros：** 不依赖 Jev 的中文能力。
**Cons：** J2、J5 已经过闸，放弃它们没有数据上的理由；成本与时延都超预算。

### Option C：归类也留在 Jev，靠调门槛

| 维度 | 评估 |
| --- | --- |
| 复杂度 | 低 |
| 成本 | 最低 |
| 时延 | 最快 |
| 风险 | 高：门槛从 0.40 扫到 0.90，没有一个点到得了 95% |

**Pros：** 最省。
**Cons：** 过不了闸。玩家的话被读错，世界就按读错的意思结算，这是最伤体验的一类错。

## Trade-off Analysis

归类错的代价和抉择错的代价不一样。角色选了一个不那么像他的动作，世界照样自洽；玩家说「把茶递给他」却被读成「把他推开」，玩家会觉得游戏不听话。所以归类的闸定得高（95%），抉择的闸定得低（70%），实测也正好落在两边。

J2 的覆盖率只有 52.5%，贴着「不少于一半」的线。把 `choice_confidence` 降到 0.45 时覆盖升到 70%、一致率 83.9%，看起来更宽裕；但门槛降了，升级给 C2 的就少了，而此刻 C2 的质量没有实测可比，所以先不动，等 Haiku 与 Sonnet 两列补跑后再定。

## Consequences

- **变容易：** 路由是数据驱动的；换模型版本或补了密钥后，重跑 `python -m tianlong eval all` 就能复核每一道闸。
- **变困难：** 没有 Claude 密钥时，自由输入的归类实际走的是 J1（约 78% 全对），玩起来会遇到读错的句子；选项输入不受影响。
- **要回头看：**
  1. 有密钥后补跑 C1、Haiku、Sonnet 三列，复核 `classify` 与 `decide_soul`。
  2. 归类集里有 6 条标注为「偷」的条目，物件对玩家不可见，内核不列为合法动作，任何路由都对不上；要么改标注，要么改布景。
  3. 英文问法模板没跟上解析器的改动，中英对比里英文一栏偏低。
  4. Jev 的真实请求有抖动（同一请求重复 5 次，判定全同的占 96.7%）。

## 2026-11-17 补记：J5 按游戏里的排法重测

上表 J5 一行原来的数（0.80 时检出 96%、误杀 6% 到 8%）是评测跑手自己拼的状态量出来的：玩家的原话用括号接在【你做的事】后面。游戏里发给 Jev 的状态不是这样排的（D-356：原话单放在模板最后标明的【玩家的话】一节）。评测改成与游戏逐字相同的状态后，在真 Jev 上重跑：

| 排法（100 句，真 Jev） | 门槛 0.70：检出 / 误杀 | 门槛 0.80：检出 / 误杀 | 过闸的门槛 |
| --- | --- | --- | --- |
| 评测旧排法，同一天重跑三次 | 100% / 18% 到 20% | 96% 到 98% / 8% 到 10% | 0.80（三次都过） |
| 游戏里的排法，四次 | 80% 到 82% / 18% 到 20% | 70% 到 74% / 4% 到 8% | 没有（0.70 到 0.85 按 0.01 细扫也没有） |
| 试验：【玩家的话】一节挪到【要核对的句子】之前，五次（只在临时拷贝的模板上试） | 100% / 18% 到 20% | 94% 到 100% / 6% 到 10% | 0.80、0.85（五次都过） |

掉的全在玩家说了话的回合：核对集里这样的句子有 25 句，其中 13 句违规，门槛 0.80 上旧排法检出 12 句，游戏里的排法四次都是 0 句；玩家没说话的 75 句不受影响（检出 35 到 37/37）。

所以 Decision 一节里「J5 核对留在 Jev，门槛由 0.70 调到 0.80」的依据不再成立。可走的路有两条，本次都没有动 `config.toml` 与 `prompts/`，等项目所有者定：

1. 按方案 7.12 的退让：`check = 'rules_only'`（只留字符串检查），并把 C3 的长度上限调低。
2. 改 `prompts/jev/j5_state.md` 的排法，把【玩家的话】一节放到要核对的句子之前，然后重跑 `python -m tianlong eval checks` 复核；试验里这样排在 0.80 上五次都过闸，`check = 'jev_first'` 与 `narration_flag = 0.80` 可以不动。

逐条的数与另外两种试过的改法见 `evals/results/findings.md`。
