# ADR-0001：确定性内核为唯一事实来源，模型只在合法清单里提议

**Status:** Accepted
**Date:** 2026-11-15
**Deciders:** 项目所有者（方案作者）；实现方按 `docs/PLAN.md` 第 1.1、1.2、4 节执行

## Context

要造的是一个没有主线的文字沙盒：开局照原著，之后只跟着各人的打算、世界规则和玩家的交互走（方案第 1 节）。几股力量互相拉扯：

- **可信。** 玩家的自由输入里会有「括号里写结果」「忽略以上规则」这类把戏（方案 2.4、11.5）。谁有权改世界，必须有一道结构上的闸。
- **分岔要传得下去。** 你先拿走帛卷，段誉就拿不到，他之后靠帛卷的步骤全部作废（方案 3.4）。这要求「世界里发生了什么」可以被精确地查询和推理。
- **可重放。** 同一局要能逐字重现，供调试和验收（方案 4.3、11.7）。
- **时延与成本。** 首字中位数不超过 3 秒；每回合约 1 美分（方案 4.3、7.13）。每回合有十几次「选一个」的判断，要快、要便宜。
- **模型会失败。** 超时、格式不合、答了清单外的东西、拒答；本开发环境里甚至没有 Claude 的密钥。游戏不能因此中断。

## Decision

采用三层分工（方案 1.2），并把它落成代码结构：

1. **内核（`src/tianlong/kernel/`）是唯一事实来源。** 纯函数、无网络无文件无时钟，随机数只来自状态里的 `seed` 与 `rng_counter`。所有状态变化只经由效果（方案 5.3）发生；每次结算后断言不变量，失败就回滚这一次。
2. **快系统（Jev）只做选择题。** 输入里带着内核给出的合法清单，输出是选项与概率；内核在概率不低于 0.15 的项里用自己的随机数取样，所以整局可重放。
3. **慢系统（Claude）负责写字与深思。** Jev 没把握或这一刻要紧时才升级；叙述只拿得到玩家视角的视图（方案 4.4），拿不到完整状态。
4. **每类调用都有退让路线**（方案 4.3 的表），最后一级是规则或模板。`--mock` 下两套模型都换成确定性的替身。
5. **契约先行、分头实现。** 先定 `docs/ARCHITECTURE.md`、`docs/CONTENT_FORMAT.md` 与内核的状态类型，再让各模块并行开发；上层模块之间不互相 import，由 `game.py` 接线。

## Options Considered

### Option A：确定性内核 + 模型在清单里提议（采用）

| 维度 | 评估 |
| --- | --- |
| 复杂度 | 高：要写完整的规则内核（约 7,000 行）与谓词、效果、不变量 |
| 成本 | 低：判断走 Jev（每回合不到 0.1 美分），只有写字与少量深思走 Claude |
| 可扩展性 | 好：换一部小说只换 `content/` 与 `prompts/`；路由由配置决定，评测后可改 |
| 熟悉度 | 借成熟设计：阵线与时钟、A-Life、GOAP、storylet、AI Director（方案 1.6） |

**Pros：** 防作弊是结构性的；分岔可证明（「前提不成立的步骤决不执行」能写成测试）；可逐字重放；模型全挂时仍能玩。
**Cons：** 内核规则多，前期投入大；世界的表现力受限于动词表与内容的覆盖面；规则表覆盖不到时人物只能 `waiting`。

### Option B：大模型当主持人，直接写世界状态

| 维度 | 评估 |
| --- | --- |
| 复杂度 | 低：一个大提示词加一份 JSON 状态 |
| 成本 | 高：每回合都要大模型读写整份状态 |
| 可扩展性 | 差：状态越长越容易自相矛盾 |
| 熟悉度 | 常见，但验收困难 |

**Pros：** 起步快；表现力不受动词表限制。
**Cons：** 玩家一句话就可能改写事实；无法重放；分岔传不传得下去全凭模型记性；违背方案 1.1 的第 1、2、7 条。

### Option C：纯规则加模板，不用模型

| 维度 | 评估 |
| --- | --- |
| 复杂度 | 中：内核同 A，叙述与解析全靠模板与关键词 |
| 成本 | 零 |
| 可扩展性 | 文字质感与自由输入的理解有硬上限 |
| 熟悉度 | 传统 MUD/IF 做法 |

**Pros：** 完全确定、零成本、零时延。
**Cons：** 自由输入只能靠关键词，叙述干瘪；做不到方案要的「人物像他自己」。它被保留为 A 的最后一级退让，也就是 `--mock` 的样子。

## Trade-off Analysis

A 与 C 共用同一个内核，区别只在内核之上有没有模型；所以选 A 不丢掉 C 的任何保证，只是多了一层可以随时关掉的提议者。B 省下了内核的投入，却丢掉了方案最看重的三样东西：防作弊、分岔可证、可重放。A 的主要代价是内核与内容的工作量，这一代价已经付出（第一批交付：内核 191 项测试、内容 25 人 22 个情境，校验零问题）。

内核里还有一个小取舍：回滚方式。整份深拷贝最简单，但 2,000 回合 × 20 个种子的试探会太慢；撤销日志最快，但要求每个效果都写逆操作。采用的是「按 schema 浅拍快照」：可变对象只存字段字典的浅拷贝，记忆、事件这类写入后不再原地修改的对象不拷贝。在小世界里一次结算约 0.6 毫秒。

## Consequences

- **变容易：** 防作弊、视角、知识边界都能写成断言式测试；任何一类判断改走 Claude 或规则只改配置（`[route]`）；没有密钥也能开发和测试全部玩法。
- **变困难：** 新玩法必须先进内核的动词、谓词或效果，内容作者不能随手写一句「然后他就被救了」；内容的前提写漏一条，分岔就传不下去，所以 P7 校验和人工过目是必需的。
- **要回头看：** M3 的 Jev 评测（方案 11.6）可能把有魂角色的抉择改回 `claude_first`；M0 已把 Jev 换到 `jev-1.14.0`，问法语言在大评测集上再比一次（D-012、D-013）；大地图上 2,000 回合试探的实际耗时还没测。
