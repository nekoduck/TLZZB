## 四、写法上的约定（给其他模块的说明）

- **`self` 与 `$角色位`。** 情境的效果里没有 `self`，所以每个 `check` 都写明 `who`。打算的 `offscreen` 里 `self` 指这个人。
- **带前提的 `schedule` 当条件效果用。** 例如 `siege` 用 `{schedule: [1, [learn …], {at: [duan_yu, …]}]}` 只让当时在山上的人得知围山；`wanjie_news` 用 `delay 0` 的 schedule 只在谷主在场时让他发作。
- **冷却用短期状态。** 通用情境开场后给相关的人加一个带期限的状态（`vetted`、`chatted`、`lesson_recent`、`custody_recent`、`standoff_recent`、`ambushed`），pick 的 `where` 排除带这些状态的人，免得每个时辰重开。
- **通用情境的 `when` 恒为 `true`（`parley` 为 `false`，只由别的情境 `open`）。** 开场条件全写在角色位的 `pick` 里，不写 `at`：世界层应在有人的地点逐个尝试绑定，绑上了才开场。
- **底线里攻击的意图写在 `act` 键**：`push`、`injure`、`bind`、`kill`。例如南海鳄神：`{verb: attack, act: kill, when: {stat: [$target, power, '<=', 0]}}`；`when` 里用 `$target` 指动作的对象。`study`、`teach` 的底线另用 `art` 键。
- **姓氏是身份。** 段誉的 `roles` 里有 `'surname:段'`，`wanjie_news` 与钟万仇的底线按它分支。
- **开局隐身。** `opening.yaml` 的 `chars.zhong_ling` 带 `statuses: [{kind: hidden}]`（梁上没人看见）；`beam_girl` 一开场就去掉它。
- **开局不在世上的物件**写 `in_world: false`，holder 与 loc 都空（机会牌「偶得」用：`chopper`、`extra_rations`、`primer`）。
- **打算的 `do` 不写 `at` 的步骤**（`follow`、`use`、`study`）在当前所在地做。
- **伤势叠加的后果。** 内核的 `injure` 是累加。按原样的 `bout_laugh`（耳光 1 级）加 6.4 的坠落（活下来也伤 2 级），段誉落到谷底时是 3 级伤，走不动，要有人照料、歇息才能恢复。这会让「带 `--lucky` 的基线」卡在谷底；需要内核或世界层定夺（例如 `injure` 取较大值而不累加，或无人照料时也能慢慢恢复）。内容这边没有为此改动规则。
