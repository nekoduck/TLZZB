  name: 'tianlong-final-review',
  description: 'Final spec-compliance review by dimension, adversarial verification of each finding, grouped fixes',
  phases: [
    { title: 'Review', detail: 'four reviewers, one spec dimension each' },
    { title: 'Verify', detail: 'one skeptic per finding' },
    { title: 'Fix', detail: 'three fixers with disjoint ownership' },
  ],
}

const BASE = `
Repo: /home/user/TLZZB — a Python 3.12 terminal text sandbox game (the opening of Jin Yong's 天龙八部 as a rule-driven world; deterministic kernel is the only source of truth, Jev = fast decision model picking from legal lists, Claude = prose + deep thought). About 1,000 tests pass. The authoritative spec is docs/PLAN.md (Chinese, 140 KB — NEVER read it whole: list headings with grep -n '^##' docs/PLAN.md and read only the line ranges you need). Contracts: docs/ARCHITECTURE.md. Deliberate deviations and choices are recorded in DECISIONS.md (about 350 one-line entries — grep it by keyword before calling something a deviation; a recorded decision is NOT a finding unless it breaks one of the eight principles of PLAN 1.1). Environment facts that are not findings: no Claude API key and no novel corpus on this machine (Claude-side smoke/evals and pipeline P1–P6 real runs are legitimately pending); content is hand-written seed content (PLAN 12 allows that before M5); style/voice samples are empty because they must be substrings of the corpus.
A hard usage budget applies: be economical, read code selectively (grep first), and stop when your scope is covered.
`

const FINDINGS = {
  type: 'object',
  properties: {
    findings: {
      type: 'array',
      items: {
        type: 'object',
        properties: {
          title: { type: 'string' },
          severity: { type: 'string', enum: ['high', 'medium', 'low'] },
          area: { type: 'string', enum: ['kernel', 'llm', 'parser', 'minds', 'world', 'storyteller', 'narrator', 'game', 'store_ui', 'pipeline', 'content', 'docs', 'evalrun'] },
          spec_ref: { type: 'string' },
          files: { type: 'array', items: { type: 'string' } },
          evidence: { type: 'string' },
          fix: { type: 'string' },
        },
        required: ['title', 'severity', 'area', 'spec_ref', 'files', 'evidence', 'fix'],
      },
    },
    covered: { type: 'string' },
  },
  required: ['findings', 'covered'],
}

const VERDICT = {
  type: 'object',
  properties: {
    confirmed: { type: 'boolean' },
    reason: { type: 'string' },
    fix: { type: 'string' },
  },
  required: ['confirmed', 'reason', 'fix'],
}

const REVIEW_RULES = `
You are a READ-ONLY reviewer: do not modify any file. Report only defects that matter: behavior that contradicts the spec sections in your scope, or breaks a PLAN 1.1 principle, or is a real bug you can demonstrate (give the reproduction: a short python snippet or the exact code path with file:line). Do not report style, missing nice-to-haves, things pending for lack of a Claude key/corpus, or recorded decisions. At most 8 findings, most severe first; severity high = wrong world outcomes, broken guarantee (anti-cheat, perspective, divergence propagation, replay, kernel purity), or a crash; medium = spec rule implemented wrongly with visible effect; low = minor. For each finding give the smallest correct fix. In 'covered' list what you checked and found correct (one line).
`

phase('Review')
const reviewed = await pipeline(
  DIMENSIONS,
  d => agent(d.prompt, { label: 'review:' + d.key, phase: 'Review', schema: FINDINGS }),
  (review, d) => {
    if (!review) return []
    const keep = review.findings.filter(f => f.severity !== 'low')
    log(d.key + ': ' + review.findings.length + ' findings, verifying ' + keep.length + ' (low severity not verified: ' + (review.findings.length - keep.length) + ')')
    return parallel(keep.map((f, i) => () =>
      agent(BASE + `
You are a skeptical verifier. A reviewer claims the following defect. Try to REFUTE it by reading the code and, where possible, running a short python snippet with .venv/bin/python (read-only: do not modify repository files; write scratch files only under /tmp). Check DECISIONS.md (grep) for a recorded decision covering it. Confirm only if the defect is real, matters, and the proposed fix is correct and consistent with the spec; if the fix is wrong but the defect is real, confirm and give the corrected fix. If uncertain, answer confirmed=false.

CLAIM: ${f.title}
SEVERITY: ${f.severity}   AREA: ${f.area}   SPEC: ${f.spec_ref}
FILES: ${f.files.join(', ')}
EVIDENCE: ${f.evidence}
PROPOSED FIX: ${f.fix}
`, { label: 'verify:' + d.key + ':' + (i + 1), phase: 'Verify', schema: VERDICT })
        .then(v => (v && v.confirmed) ? { ...f, fix: v.fix || f.fix, verdict: v.reason, dim: d.key } : null)))
  },
  (verified, d) => (verified || []).filter(Boolean),
)

const confirmed = reviewed.filter(Boolean).flat()
const lows = []
log('confirmed findings: ' + confirmed.length)
if (!confirmed.length) return { confirmed: [], fixes: [] }

const BUNDLES = [
  { key: 'core', areas: ['kernel', 'llm'], paths: 'src/tianlong/kernel/**, src/tianlong/llm/**, src/tianlong/content/**, src/tianlong/config.py, tests/kernel/**, tests/llm/**, tests/content/**' },
  { key: 'play', areas: ['parser', 'minds', 'world', 'storyteller', 'narrator', 'game'], paths: 'src/tianlong/parser/**, src/tianlong/minds/**, src/tianlong/world/**, src/tianlong/storyteller/**, src/tianlong/narrator/**, src/tianlong/game.py, prompts/** (except prompts/pipeline), and the tests of those modules (tests/parser, tests/minds, tests/world, tests/storyteller, tests/narrator, tests/game, tests/e2e)' },
  { key: 'delivery', areas: ['content', 'pipeline', 'docs', 'store_ui', 'evalrun'], paths: 'content/**, src/tianlong/pipeline/**, prompts/pipeline/**, src/tianlong/store/**, src/tianlong/ui/**, src/tianlong/evalrun/**, src/tianlong/__main__.py, README.md, docs/** (not docs/PLAN.md), evals/**, and their tests (tests/pipeline, tests/store, tests/ui, tests/evalrun, tests/evals, tests/acceptance only to add tests)' },
]

phase('Fix')
const fixes = await parallel(BUNDLES.map(b => () => {
  const mine = confirmed.filter(f => b.areas.includes(f.area))
  if (!mine.length) return Promise.resolve({ bundle: b.key, report: 'nothing to fix' })
  const list = mine.map((f, i) => `${i + 1}. [${f.severity}] ${f.title}\n   spec: ${f.spec_ref}\n   files: ${f.files.join(', ')}\n   evidence: ${f.evidence}\n   fix: ${f.fix}\n   verifier: ${f.verdict}`).join('\n')
  return agent(BASE + `
You are the fixer for bundle '${b.key}'. Other fixers work in parallel on other paths. OWNED PATHS: ${b.paths}. Do not touch other paths; no git commands that change state. All world-state changes go through kernel effects; no names/plot in src/; mock mode stays deterministic and offline.
Keep a progress log at docs/wip/fix-${b.key}.md (append one line per finished item; if it exists, a previous run was interrupted — read it and resume).
Fix these verified findings, most severe first. For each: write a regression test that fails before and passes after, make the smallest correct change, and note a one-line decision in Chinese if the fix involves a choice. If a finding turns out to need a change outside your paths, do the part inside your paths and report the rest precisely.
${list}
When done: run the tests of your paths, then the full suite once (.venv/bin/python -m pytest -q; it takes about 10 minutes — run it once at the end), and .venv/bin/ruff check src tests scripts. The lucky baseline must still hit all marks (tests/content/test_baseline.py) and tests/acceptance must stay green.
Final answer: per finding: fixed / partly / not fixed + what changed (files) + the decision line; test counts; anything left.
`, { label: 'fix:' + b.key, phase: 'Fix' }).then(r => ({ bundle: b.key, count: mine.length, report: r }))
}))

return { confirmed: confirmed.map(f => ({ title: f.title, severity: f.severity, area: f.area, spec: f.spec_ref, files: f.files, fix: f.fix })), fixes }
